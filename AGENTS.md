# Release history
For each published update, increment dist/client/build-version.js and prepend an accurate release entry to PATCH_NOTES in dist/client/patch-notes.js. Preserve all previously published entries. The patch notes page must remain accessible from the main menu. Keep cache-busting versions aligned with BUILD_VERSION. Run npm test before publication.
For each balance change, include structured `balance` rows on the release with `subject`, `stat`, numeric `before` and `after`, and `lowerIsBetter: true` for costs or penalties. The patch notes renderer shows before/after values with green buff arrows, red nerf arrows and neutral unchanged values. New agents have no previous stats; do not invent them.
